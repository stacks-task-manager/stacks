# App component inventory

This is the discovery index for React components in `packages/app`. Before adding UI, check this file and the owning barrel. The goal is to reuse the existing primitive or extend it at its owning layer instead of creating a parallel component.

## Reuse rules

1. Start with `components/common` for generic primitives and `widgets/common` for shared composed widgets.
2. Use a domain component/widget when behavior already depends on task, person, calendar, project, or sidebar state; extend that owning module rather than copying it.
3. Treat `views/` as route composition boundaries. A view is not a reusable primitive unless its behavior is extracted into a widget.
4. Import with `app/...` paths. Prefer the closest barrel (`app/components/common`, `app/widgets/task`, and so on); use a deep import only when the module is intentionally internal.
5. Preserve interaction invariants when extending: store mutations go through actions, subscriptions use `Store.use()`, user feedback uses `window.toaster`, and interactive controls need stable test ids.

`Index-linked` means the module is reachable from an `index.ts`/`index.tsx` export graph. Because `export *` does not re-export defaults, check whether the specific symbol is a named or default export before importing from a barrel. `Direct` means the module is imported directly rather than linked through a barrel.

## Maintenance

When adding, moving, exporting, or deleting a component:

1. Add or move the component in the correct layer: `components/common` for a primitive, `widgets/common` for a shared composed block, `widgets/<domain>` for domain behavior, or `views/` for route composition.
2. Update the relevant `index.ts` barrel and this inventory row.
3. If a component becomes shared, move it at the owning layer instead of creating an app-level copy.
4. Run `yarn prettier --write packages/app/COMPONENTS.md` after editing.

See also [UTILS.md](./UTILS.md) for pure helpers, shared hooks, and store primitives.
